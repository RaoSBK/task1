# Customer Support Ticket Management System

Backend service for a Customer Support Ticket Management System built with **FastAPI**, **PostgreSQL**, **SQLAlchemy 2.0**, **Alembic**, **Pydantic v2**, and **Pytest**.

## 2. API Endpoints

### Authentication & Authorization (RBAC)

| Method | Endpoint | Access | Description | Status Codes |
|---|---|---|---|---|
| `POST` | `/api/v1/auth/register` | Public | Register customer account. Role escalation is forbidden; always assigns `customer`. | `201`, `409`, `422` |
| `POST` | `/api/v1/auth/login` | Public | Authenticate with email/password; returns JWT access token. | `200`, `401`, `422` |
| `GET` | `/api/v1/auth/me` | Authenticated | Retrieve current user profile. Never returns password hashes. | `200`, `401` |
| `GET` | `/api/v1/auth/admin-only` | Admin | Route restricted strictly to `admin` role. | `200`, `401`, `403` |
| `GET` | `/api/v1/auth/agent-only` | Agent / Admin | Route restricted to support agents and administrators. | `200`, `401`, `403` |

### Core Ticket Management (Step 3)

| Method | Endpoint | Access | Description | Status Codes |
|---|---|---|---|---|
| `POST` | `/api/v1/tickets` | Authenticated | Create a ticket. Customers create for themselves; tickets start as `open` and unassigned. | `201`, `401`, `422` |
| `GET` | `/api/v1/tickets` | Authenticated | List tickets with filtering and pagination. Scoped by role: Customers see only their own; Agents see only assigned; Admins see all. | `200`, `401`, `403`, `422` |
| `GET` | `/api/v1/tickets/{id}` | Authenticated | Retrieve a single ticket. Enforces ownership: customers can only view their own; agents only view assigned; admins view any. | `200`, `401`, `403`, `404` |
| `PATCH` | `/api/v1/tickets/{id}` | Authenticated | Update permitted ticket fields according to role allowlist. Logs status transitions to `ticket_history`. | `200`, `401`, `403`, `404`, `422` |
| `PATCH` | `/api/v1/tickets/{id}/assign` | Admin | Assign ticket to a verified support agent (`role=agent`) or unassign (`null`). | `200`, `400`, `401`, `403`, `404`, `422` |

> *Note: Endpoints are accessible both via `/api/v1/tickets` and direct root alias `/tickets`.*

## 3. RBAC Scoping, Filtering & Allowlist Rules

### Ownership Scoping
- **Customer**: Can only create tickets for themselves, view their own tickets, and retrieve their own tickets. Attempting to filter by another customer's ID or filter by assigned agent returns `403 Forbidden`.
- **Agent**: Can view and retrieve tickets assigned to them (`assigned_agent_id == current_user.id`). Attempting to filter by or view other agents' tickets returns `403 Forbidden`.
- **Admin**: Has global visibility across all tickets and can filter by any customer or agent.

### Update Field Allowlist
| Role | Permitted Fields | Forbidden Fields | Behavior on Violation |
|---|---|---|---|
| **Customer** | `title`, `description` | `status`, `priority`, `assigned_agent_id` | Returns `403 Forbidden` |
| **Agent** | `title`, `description`, `status`, `priority` | `assigned_agent_id` (assignment is admin-only) | Returns `403 Forbidden` |
| **Admin** | `title`, `description`, `status`, `priority` | — | Full update rights |

### Assignment Rules (`PATCH /tickets/{id}/assign`)
- **Restricted to Admin**: Non-admins receive `403 Forbidden`.
- **Agent Verification**: Target user must exist (`404 Not Found` if missing) and must possess the `agent` role (`400 Bad Request` if assigned to customer/admin).
- **Unassigning**: Passing `"assigned_agent_id": null` safely clears the assignment.

### Validated Pagination
- `page`: Minimum `1`, default `1`.
- `page_size`: Minimum `1`, maximum `100`, default `20`.
- Response format:
  ```json
  {
    "items": [...],
    "total": 45,
    "page": 1,
    "page_size": 20,
    "pages": 3
  }
  ```

## 4. Administrative CLI Commands

```bash
# Create an administrator
python -m app.cli create-user --name "Admin User" --email "admin@example.com" --role admin --password "StrongPass123!"

# Create a support agent
python -m app.cli create-user --name "Agent User" --email "agent@example.com" --role agent --password "StrongPass123!"

# Bootstrap initial administrator if none exists
python -m app.cli bootstrap-admin --email "admin@example.com" --password "StrongPass123!"
```

## 5. Setup and Commands

### Install Dependencies
```bash
pip install -r requirements.txt
```

### Run Migrations
```bash
alembic upgrade head
alembic current
```

### Run Automated Tests
```bash
pytest -v
```

### Start the FastAPI Server
```bash
uvicorn app.main:app --host 0.0.0.0 --port 8000 --reload
```

Interactive Documentation:
- Swagger UI: `http://localhost:8000/api/v1/docs`
- Redoc: `http://localhost:8000/api/v1/redoc`
